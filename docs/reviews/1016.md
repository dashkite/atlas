# Release Notes

This release refactors the core architecture of `@dashkite/atlas` to encapsulate domain state into behavioral classes, replace imperative control flow and mutable accumulators with declarative `@dashkite/joy` pipelines, enforce strict boundary contracts, and eliminate synchronous filesystem I/O.

### Behavioral Class Encapsulation

Core graph data structures, URL resolvers, and bundling utilities have been transitioned from static namespace objects and loose context bags into cohesive classes with static `@make` constructors and instance methods:

- **Graph & Index Categories**:
  - [`ComponentGraph`](file:///Users/dan/repos/dashkite/central-park/.tempo/repos/atlas/src/categories/component-graph.coffee#L1-L24), [`ModuleGraph`](file:///Users/dan/repos/dashkite/central-park/.tempo/repos/atlas/src/categories/module-graph.coffee#L1-L35), [`TreeIndex`](file:///Users/dan/repos/dashkite/central-park/.tempo/repos/atlas/src/categories/tree-index.coffee#L4-L30), and [`Trie`](file:///Users/dan/repos/dashkite/central-park/.tempo/repos/atlas/src/categories/trie.coffee#L1-L17) now encapsulate their internal collections (`vertices`, `edges`, `attributes`, `bindings`, `children`) and expose fluent instance methods.
- **Resolvers & Registry**:

### Critical & High-Value Findings

#### 1. Public API & Option Naming Divergence (`directory` vs `cwd` vs `root`)
Removing legacy option fallbacks introduced a split in option naming across sibling entry points and resolvers:
- [`bundle`](file:///Users/dan/repos/dashkite/central-park/.tempo/repos/atlas/src/bundle.coffee#L201-L205) now normalizes `options.directory ? process.cwd()` and translates it to `cwd: context.options.directory` when calling [`analyze`](file:///Users/dan/repos/dashkite/central-park/.tempo/repos/atlas/src/bundle.coffee#L214) and [`ingest`](file:///Users/dan/repos/dashkite/central-park/.tempo/repos/atlas/src/bundle.coffee#L224). Passing `{ cwd }` or `{ root }` to `bundle` is now silently ignored.
- [`generate`](file:///Users/dan/repos/dashkite/central-park/.tempo/repos/atlas/src/generate.coffee#L58-L62), [`ingest`](file:///Users/dan/repos/dashkite/central-park/.tempo/repos/atlas/src/ingest.coffee#L14-L15), and [`analyze`](file:///Users/dan/repos/dashkite/central-park/.tempo/repos/atlas/src/helpers/analyze.coffee#L5-L8) standardize on `options.cwd ? process.cwd()`. Passing `{ directory }` to `generate` is silently ignored.
- [`ApplicationResolver.make`](file:///Users/dan/repos/dashkite/central-park/.tempo/repos/atlas/src/resolvers/application.coffee#L16-L18) and [`NodeResolver.make`](file:///Users/dan/repos/dashkite/central-park/.tempo/repos/atlas/src/resolvers/node.coffee#L47-L49) accept only `config.root`, whereas [`LocalResolver.make`](file:///Users/dan/repos/dashkite/central-park/.tempo/repos/atlas/src/resolvers/local.coffee#L11-L16) requires `config.root` alongside `config.cwd` (stored internally as `@workingDirectory`).

**Recommendation**: Align top-level entry points (`bundle`, `generate`, `ingest`, `analyze`) on a single canonical option name (`directory` or `cwd`) so callers do not have to remember different option keys for `bundle` vs `generate`.

#### 2. Breaking Signature & Export Changes on Re-Exported Symbols
Several internal modules re-exported from [`src/index.coffee`](file:///Users/dan/repos/dashkite/central-park/.tempo/repos/atlas/src/index.coffee#L16-L52) changed their calling conventions:
- [`Compiler.apply`](file:///Users/dan/repos/dashkite/central-park/.tempo/repos/atlas/src/functors/compiler.coffee#L65-L109) changed from `Compiler.apply(componentGraph, options = {})` (reading `options.compact ?= true`) to `pipe [ createContext, embedTree ]` where [`createContext`](file:///Users/dan/repos/dashkite/central-park/.tempo/repos/atlas/src/functors/compiler.coffee#L65) has signature `( graph, compact = true )`. **Subtle footgun**: Any external caller passing the previous options object `{ compact: false }` as the second argument will pass a truthy object into `compact`, silently enabling compaction instead of disabling it.
- [`ModuleGraph#setAttribute`](file:///Users/dan/repos/dashkite/central-park/.tempo/repos/atlas/src/categories/module-graph.coffee#L28) and [`TreeIndex#bind`](file:///Users/dan/repos/dashkite/central-park/.tempo/repos/atlas/src/categories/tree-index.coffee#L17) dropped variadic support and now strictly require tuple destructuring (`( vertex, [ key, value ] )` and `( path, [ label, target ] )`), in addition to moving from static namespace functions to instance methods.
- `Resolver` in [`src/index.coffee`](file:///Users/dan/repos/dashkite/central-park/.tempo/repos/atlas/src/index.coffee#L27) was renamed to [`BundleResolver`](file:///Users/dan/repos/dashkite/central-park/.tempo/repos/atlas/src/functors/resolver.coffee#L27) and changed from `Resolver.apply(components, index, resolvers)` to `(BundleResolver.make components, index, resolvers).resolve()`.
- Meanwhile, [`src/functors/baseline.coffee`](file:///Users/dan/repos/dashkite/central-park/.tempo/repos/atlas/src/functors/baseline.coffee#L49-L55) was changed from `Baseline = { apply }` to a default-exported bare function `functor = ( graph ) ->`, creating an interface asymmetry with the remaining functors (`Compaction.apply`, `Compression.apply`, `Resolution.apply`, `Serialization.apply`, `Quotient.apply`, `Compiler.apply`).
- *Pre-existing issue noted in [`src/index.coffee`](file:///Users/dan/repos/dashkite/central-park/.tempo/repos/atlas/src/index.coffee#L12)*: `import Resolvers, { App, NPM, Metarepo } from "./resolvers"` imports nonexistent named exports from [`src/resolvers/index.coffee`](file:///Users/dan/repos/dashkite/central-park/.tempo/repos/atlas/src/resolvers/index.coffee#L8) (which exports `{ Application, Node, CDN, Local, Registry }`), exporting `undefined` for `App`, `NPM`, and `Metarepo`.

#### 3. Inconsistent Scoped/Unscoped Pathname Decoding Across Resolvers
[`CDNResolver`](file:///Users/dan/repos/dashkite/central-park/.tempo/repos/atlas/src/resolvers/cdn.coffee), [`LocalResolver`](file:///Users/dan/repos/dashkite/central-park/.tempo/repos/atlas/src/resolvers/local.coffee), and [`NodeResolver`](file:///Users/dan/repos/dashkite/central-park/.tempo/repos/atlas/src/resolvers/node.coffee) all decode the identical URL Codex templates (`"/{scope}/{versioned}/{path*}"` vs `"/{versioned}/{path*}"`), but were refactored into three different patterns:
- [`LocalResolver` (`decodePathname`)](file:///Users/dan/repos/dashkite/central-park/.tempo/repos/atlas/src/resolvers/local.coffee#L32-L36):
  ```coffee
  if pathname.startsWith "/@"
    Codex.decode SCOPED_TEMPLATE, pathname
  else
    Codex.decode UNSCOPED_TEMPLATE, pathname
  ```
- [`NodeResolver` (`decodePathname`)](file:///Users/dan/repos/dashkite/central-park/.tempo/repos/atlas/src/resolvers/node.coffee#L11-L16):
  ```coffee
  match = decode TEMPLATE.scoped, pathname
  if match?.scope.startsWith "@"
    match
  else
    decode TEMPLATE.unscoped, pathname
  ```
  (Parses every unscoped URL twice.)
- [`CDNResolver` (`decodeTemplate`)](file:///Users/dan/repos/dashkite/central-park/.tempo/repos/atlas/src/resolvers/cdn.coffee#L27-L32):
  ```coffee
  try
    match = urlDecode SCOPED_TEMPLATE, pathname
    if match.scope.startsWith "@" then match else throw new Error
  catch
    urlDecode UNSCOPED_TEMPLATE, pathname
  ```
  (Still uses `try/catch` for normal control flow on unscoped packages, and relies on `catch` to swallow a `TypeError` when `match` is null/undefined on single-segment unscoped package URLs like `"atlas://cdn@unpkg/foo@1.0.0"`.)

**Recommendation**: Standardize `CDNResolver` and `NodeResolver` on the `pathname.startsWith "/@"` check used in `LocalResolver` (or extract a shared module-pathname decoder helper).

### Code Quality & Idiom Observations

- **Unused Dependency in [`package.json`](file:///Users/dan/repos/dashkite/central-park/.tempo/repos/atlas/package.json#L53)**: `"@dashkite/generic": "^0.9.32"` was added to `dependencies` in `package.json`, but `@dashkite/generic` is not imported anywhere in `src/` or `test/`. It should be removed if unneeded.
- **Forced `pipe` Wrapping on Multi-Argument Methods**: In [`BundleResolver#processModule`](file:///Users/dan/repos/dashkite/central-park/.tempo/repos/atlas/src/functors/resolver.coffee#L75-L83), [`CDNResolver#decode`](file:///Users/dan/repos/dashkite/central-park/.tempo/repos/atlas/src/resolvers/cdn.coffee#L66-L72), and [`CDNResolver#resolve`](file:///Users/dan/repos/dashkite/central-park/.tempo/repos/atlas/src/resolvers/cdn.coffee#L77-L83), declaring methods as `pipe` pipelines required allocating intermediate carrier objects (`{ directory, url, descriptor }`, `{ parsed, match }`, `{ descriptor, data }`) just to thread earlier arguments across unary steps. Where steps are not naturally unary, a direct 2-line method or helper composition is cleaner and avoids unnecessary per-call object allocation.
